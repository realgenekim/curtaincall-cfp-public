01 · Admin

Program dashboard

The Monday-morning page. One glance answers: is the CFP on pace, is the committee keeping up, and which accepted speakers are about to make me chase them?

What this screen does · key judgment calls

Numbers a coordinator can act on

count-firstNo vanity charts. Every stat is a work queue with a size: 47 submissions, 31 rated, 12 speakers missing a headshot. If a number can't be clicked into a filtered list, it isn't on this page.

Attention list > analytics

Sessionboard buries "what's broken" under a submissions-pacing line chart. We invert it: the middle of the page is a ranked, severity-coded list of things that need a human, each with a one-click action.

Evaluation progress by person

Committee progress is per-reviewer, not an aggregate percentage — because the fix is always "nudge Marcus," never "raise the average." One-click reminder per row.

Speed is a design element

no spinnersWhole page is one server-rendered response. The latency badge in the app bar is real and shown on purpose: the incumbent's slowness is the thing swyx complained about three times.

02 · Admin

Form builder

One CFP form, organised in sections, with a live public URL. Drag a field in from the left, set its rules on the right. The thing a production coordinator builds once in twenty minutes and edits four times before the CFP closes.

What this screen does · key judgment calls

One form, not a form factory

scope callSessionboard makes you create Form #2, Form #3, Form #4 and then wire routing between them. AIE runs one call for speakers with a track picker. So: a single form, sections instead of a wizard, tracks as a field. Multiple forms is a later capability, not a v1 concept to learn.

Three panes, no modal dialogs

Palette · canvas · inspector, all visible at once. Editing a field never covers up the form. Every change saves on blur and shows on the public page immediately — the version chip in the header is the only "save" ceremony.

Conditional logic in one sentence

Rules read as English — "If Track is Workshops, show Room setup + AV needs" — and the affected fields get a violet rail on the canvas so you can see the conditional shape of the form without opening anything.

Close date + emails live here

Close date, reminder, thank-you email and submission limit are properties of the form, not settings buried three menus away. The public URL sits at the top with a copy button, because that is the thing you actually go looking for.

03 · Public

Call for speakers

The public face of the whole product. One page, no wizard, no account wall — the speaker writes their abstract and hits submit; the account is created behind them.

What this screen does · key judgment calls

Kill the 5-step wizard

biggest callSessionboard's public form is Welcome → Account → Submission → Participant → Review. Five pages before you can type a title, and a sign-up wall in step 2. We ship one scrolling page, account created on submit from the email already given. 49 people abandoned last year's form; 38 of them on the abstract.

The sidebar sells the slot

Deadline, what the committee actually rewards, track sizes, and "who reviews this" sit beside the form the entire time. A CFP is a pitch to the speaker as much as the other way round.

Honest counters, honest rules

Character counts, minimums, and the review timeline are stated up front, not enforced by a red toast after submit. Draft is saved locally every keystroke — a lost abstract is the one unforgivable failure here.

Co-speakers cost one click

Add a co-speaker inline, and they get their own portal account and their own tasks. No "participant" step, no separate invite flow, no admin doing data entry later.

04 · Speaker

Speaker portal

Where an accepted speaker lands from the acceptance email. Status first, then the short list of things only they can do. No dashboard, no navigation to learn.

What this screen does · key judgment calls

Status is the headline, not a badge

swyx: "a key part"The single most-asked speaker question is "did I get in?". It's the first 46 pixels of the page, in words, with the date it was decided. Under review and Declined get the same treatment — a declined speaker sees a real reason, not a dead page.

Tasks are a checklist, not a project plan

Five rows, each with a due date and an inline control — upload here, confirm here. No task-detail pages, no sub-forms to open. Overdue is red and sorted to the top. The bar at the top is the same 61% the admin dashboard shows.

Calendar without an integration

.ics onlyDownload or re-send the invite as a plain .ics attachment — works with Gmail, Outlook and iCal without OAuth. Room was assigned after the first invite, so the card shows the change and offers a re-send; updates carry the same UID so calendars update in place.

Everything stays editable

Bio and abstract can be edited after acceptance (AIE doesn't use edit locks) — but edits after the program guide deadline show a warning about what's already printed.

05 · Admin · ★ the crown jewel

Review board

Every submission, every reviewer's individual score, and every reviewer's comment — on one page, without a click. This is the screen that decides whether a program committee likes the product.

What this screen does · key judgment calls · field-proven at ITRev

Never collapse reviewers into a number

doctrineA mean of 3.4 hides the case that matters: Gene 5.0 / Christina 1.5. Row two shows every individual score and every individual comment inline. Disagreement is the signal a committee meets about — it must be visible while scrolling, not one click down.

One dense page, no wizard

Sessionize walks you through submissions one at a time. We put 400 rows on a page so you can compare, sort by mean, and see the shape of the field. Two visual rows per submission is the compromise that keeps density and readability.

Score without leaving the row

The logged-in reviewer's own chip is outlined; the cursor row opens an inline 1–5 + comment box. j/k moves, 1–5 scores, c comments, a/d accepts or declines. A committee member can rate 47 submissions without touching the mouse.

The speaker is part of the submission

Headshot thumbnail with a hover card: bio, affiliation, socials, past talks. Our old tool's biggest gap — reviewers kept opening another tab to answer "who is this person?".

Filters that match real triage

spam is realStatus chips with counts, free-text search across title + abstract + speaker, a "hide accepted/declined" toggle for the last-mile pass, and a low-signal filter for the unserious submissions swyx warned about. Bulk-decline from the checkbox column.

Coverage flagged, not buried

Rating counts turn red under 3. The committee's job is coverage before consensus, and the board says so on every row.

By reviewer

The same 47 submissions, pivoted the other way: who has done the work, how each person scores relative to the room, and what each of them would put on stage if it were up to them.

What this screen does · key judgment calls

Coverage before consensus

The chair's first job is getting every submission to three ratings. Coverage is the top line of every card, with a one-click reminder that names the exact submissions that person still owes.

Schedule builder

Rooms as columns, half-hours as rows, accepted-but-unscheduled sessions in a tray on the left. Drag a card into a cell; the server checks for conflicts and tells you what it found before you let go.

What this screen does · key judgment calls

Conflicts are explained, not just flagged

the hard partA red border is useless on its own. The tooltip names the person, the other session, the room and the time — and offers the two fixes (move this, or move the other one) inline. Speaker double-booking, room double-booking and track collisions are three different messages.

The tray is the to-do list

"9 unscheduled" from the dashboard lands you here with those 9 in the tray, sorted by constraint difficulty — workshops and multi-speaker sessions first, because they're the ones that box you in.

One grid, five lenses

Day / Week / Track / Room / List are views of the same data, not five screens. Track view swaps the columns for tracks; List view is the printable one the ops team tapes to the green-room wall.

Moving a session moves the invites

A drop that changes time or room queues an updated .ics for every speaker on the card — same UID, so calendars update in place. The count of pending re-sends sits in the toolbar until you send them.

Comms

Four templates do 95% of the work: acceptance, decline, reminder, schedule change. Edit on the left, see exactly what a real speaker receives on the right, then look at the log of what was actually sent to whom.

What this screen does · key judgment calls

Preview with real data, always

no loremThe preview renders against an actual speaker record you pick from a dropdown — merge fields filled in, .ics attached, exactly the bytes that will land. Nobody should discover {{room}} was empty after 18 emails went out.

Calendar invites are an attachment, not an integration

Templates carry an "attaches .ics" badge. Plain iCalendar files work in Gmail, Outlook and Apple Calendar with no OAuth, and re-sends reuse the event UID so a room change updates in place instead of creating a second entry.

The send log is per speaker

"Did Ana get the acceptance?" is the question the ops team asks daily. Every send is a row: template, time, opened, bounced, and the exact rendered body — one click from the speaker's record.

Nothing sends without a human

Reminders are scheduled and shown as a queue with a count and a time; acceptance and decline batches always require an explicit review-and-send. The one-way door gets a confirmation, everything else is undo-able.

The published schedule, and the four lines of HTML that put it on the conference marketing site. Same data as the schedule builder — publishing is a state change, not an export.

What this screen does · key judgment calls

The embed is a real page, not an iframe of an app

speedServer-rendered HTML with inline styles, cached at the edge, no JavaScript required to read the agenda. It loads on conference wifi on a three-year-old phone — the actual usage condition.

Mobile is the primary form

Attendees read the agenda standing in a hallway. Day tabs, track filter chips, and a tap-to-expand session detail — designed at 375px first and widened, not the other way round.

Publishing is explicit and reversible

Unpublished changes are counted in the admin bar with a diff ("3 sessions moved, 1 added") so nobody discovers a half-finished Day 3 on the public site. One button publishes; the previous version stays servable.

One URL, three shapes

The same route serves the embed, a standalone page, and an .ics feed attendees can subscribe to. Marketing takes the snippet, attendees take the calendar link, nobody asks engineering for an export.
